# Kundan — QA Engineer Portfolio

[![QA portfolio checks](https://github.com/kundanmeruva1/kundanmeruva-qa-portfolio/actions/workflows/playwright.yml/badge.svg)](https://github.com/kundanmeruva1/kundanmeruva-qa-portfolio/actions/workflows/playwright.yml)

A practical QA engineering showcase covering browser automation, REST API validation, risk-based testing, database test ideas, and continuous integration.

> **Project transparency:** The automation examples target public demo services (Sauce Demo and JSONPlaceholder). They are portfolio/practice projects, not client engagements or production-system tests. Test results and performance metrics are not claimed unless generated by an actual run.

## What this repository demonstrates

| Area | Evidence |
|---|---|
| UI automation | Playwright + TypeScript, Page Object Model, reusable fixtures, end-to-end user journeys |
| API automation | REST status, contract shape, data assertions, negative cases, create-request behavior |
| Test design | Test strategy, risk assessment, test scenarios, defect-report template |
| Data validation | SQL examples for order, item, and customer consistency checks |
| CI/CD | GitHub Actions matrix for portfolio, e-commerce E2E, and API suites |
| Diagnostics | HTML report, JUnit XML, trace, screenshot, and video on failure |

## Flagship project: E-commerce quality checks

The E2E suite uses the public [Sauce Demo](https://www.saucedemo.com/) training application.

Coverage includes:
- Successful and unsuccessful authentication
- Product inventory and sorting
- Cart add/remove behavior
- Checkout form validation
- Completing a purchase journey and verifying the confirmation state

The code is organized with page objects and a shared fixture so selectors and workflows stay maintainable.

## API automation

The API suite targets [JSONPlaceholder](https://jsonplaceholder.typicode.com/), a public fake REST API intended for testing and prototyping.

Coverage includes:
- Retrieve a post and validate required fields and types
- Retrieve a user and validate nested address data
- Validate a not-found response
- Submit a create request and validate the returned representation

JSONPlaceholder simulates writes; a successful POST does not mean data was durably stored.

## Run locally

Requirements: Node.js 20+, Python 3, and a network connection for the public demo suites.

```bash
npm install
npx playwright install chromium
npm test
```

Run one suite:

```bash
npm run test:portfolio
npm run test:e2e
npm run test:api
```

Optional environment overrides:

```bash
E2E_BASE_URL=https://www.saucedemo.com npm run test:e2e
API_BASE_URL=https://jsonplaceholder.typicode.com npm run test:api
```

View the generated HTML report:

```bash
npm run report
```

## CI/CD

GitHub Actions runs three independent jobs on pushes to main/feature branches, pull requests to main, and manual dispatch. Each job installs Chromium, executes one Playwright project, and uploads the HTML report and test diagnostics as a workflow artifact.

Open the [Actions tab](https://github.com/kundanmeruva1/kundanmeruva-qa-portfolio/actions) to inspect actual run status and download artifacts. The README badge reflects the workflow's latest status; it is not a manually asserted pass rate.

## Publish the portfolio with GitHub Pages

1. Open repository **Settings → Pages**.
2. Under **Build and deployment**, select **Deploy from a branch**.
3. Choose **main** and **/(root)**, then save.
4. Wait for GitHub to publish the site. The Pages settings show the confirmed URL.
